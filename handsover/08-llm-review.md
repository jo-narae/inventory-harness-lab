## 1. 출발점 — 사람의 요청과 세 갈래

입력은 한 줄이었다. *"사람의 최종 판단 전에 정성적 검토를 담당하는 LLM Review 계층을 두고
싶다. CI PASS 후 실행하고, 결과는 PR 코멘트로."*

시점과 기록처는 정해져 있었지만, 결과가 크게 갈리는 것 셋이 비어 있어 먼저 물었다.

| 물은 것 | 사람의 답 | 갈렸다면 |
|---|---|---|
| 루프를 되돌릴 수 있나 | **경고 — 되돌리지 않음** | 게이트였다면 `03 §2` FAIL 갈래 복귀와 시도 횟수 규칙을 새로 정해야 했다 |
| 무엇이 실행하나 | **에이전트가 로컬에서 실행 후 `gh`로 코멘트** | CI 워크플로였다면 `ANTHROPIC_API_KEY` 시크릿과 `workflow_run` 구성이 필요했다 |
| 어디까지 만드나 | **원본 문서 정의만** | 워크플로까지였다면 `.github/workflows/` 에 파일이 하나 더 생겼다 |

## 2. 완료한 것

### `02 §5` — LLM 검토 신설

`§1`의 층 표가 두 층에서 **세 층**이 됐고, `구속력` 열이 새로 생겼다.

| 층 | 판정자 | 구속력 |
|---|---|---|
| 기계 검증 | `npm run verify` | 게이트 |
| **LLM 검토** | **AI** | **경고** |
| 사람 검증 | 사람 | 게이트 |

`§5`가 정한 것.

| 항목 | 규칙 |
|---|---|
| 시점 | CI가 PASS한 뒤, 사람 검증을 요청하기 전 |
| 실행자 | AI. 로컬에서 검토하고 결과를 그 PR에 코멘트로 남긴다 |
| 대상 | 이 PR의 diff와, 그 diff가 닿은 원본 — 해당 Issue의 종료 조건 · `01` · `06` |
| 보는 것 | 의도와의 어긋남 · 판정하는 것이 없는 자리 · 놓친 엣지 케이스 · 유지보수를 어렵게 할 구조 |
| 보지 않는 것 | 기계 검증이 이미 판정한 것 — 타입·린트·경로 규칙·불변식 |
| 시도 횟수 | 세지 않는다 (`03 §1`) |
| 결과 기록 | 지적이 없어도 남긴다 |
| 지적의 처리 | 사람이 정한다. 고치기로 하면 **사람 검증 반려와 같은 경로** (`03 §6.3`) |

### `02 §3` — 경고 층이 처음 생겼다

직전 세션의 `§3`은 "Prepare를 제외한 모든 단계는 게이트다. **현재 별도의 경고 단계는 없다**"
였다. 그 문장이 이번에 깨졌으므로 절을 다시 썼다.

| 구분 | 여기에 속하는 것 |
|---|---|
| 게이트 | `npm run verify`의 모든 단계 (Prepare 제외) · 사람 검증 (`§6`) |
| 경고 | LLM 검토 (`§5`) |

그리고 소절을 하나 붙였다 — **"경고가 완료를 막지 않는다는 것의 뜻"**. 경고는 *지적을 받아들일지
사람이 정한다*는 뜻이지 *돌리지 않아도 된다*는 뜻이 아니다. 실행하지 않은 것을 지적이 없는
것으로 보고하지 않는다.

### `03 §5` — LLM 검토 코멘트 양식

PR 코멘트 표에 `LLM 검토 완료 | AI` 행을 넣고, **넷 중 이것만 양식을 고정**했다. 나머지 셋은
사람이 그때그때 쓰는 것이지만 이것은 AI가 매번 같은 자리에 남기기 때문이다.

```
## 🔍 LLM 검토 — <지적 N건 | 지적 없음 | 실행하지 못함>

- 대상: <검토한 diff 범위>
- 지적:
  - <파일:줄> — <무엇이 어긋나 보이는가> · 근거: <원본 위치 또는 종료 조건>
- 판정이 비는 자리: <새로 생긴 규칙 중 판정하는 것이 없는 항목 | 없음>
- 경고다 (`02 §3`). 처리 여부는 사람이 정한다
```

제목 줄에 `실행하지 못함`을 둔 것은 `02 §3`의 "실행하지 않은 것을 지적 없음으로 보고하지
않는다"를 양식으로 강제한 것이다.

## 3. 어떻게 좁혀갔나 — 판단이 갈렸던 여섯 곳

1. **`02`가 소유한다.** 처음에 `03`(루프)에 넣을지 저울질했지만, `00-ssot.md §2`가 검증의
   **층과 판정 방법**을 `02`의 몫으로 정해 놓았다. `03`은 판정 **이후**만 다룬다. 그래서 층의
   정의는 `02 §5`, 코멘트 양식은 `03 §5`로 갈랐다.
2. **번호를 밀었다.** 사람 검증을 `§5` → `§6`으로 옮기고 LLM 검토를 `§5`에 넣었다. 뒤에 `§6`
   으로 붙이면 참조 수정이 없어 싸지만, **읽는 순서가 지나가는 순서와 어긋난다**. 절 번호로
   라우팅하는 문서라 순서가 곧 의미다. 참조 4곳(`03` 3곳 · `AGENTS.md` 1곳)을 고치는 값을 치렀다.
3. **경고인 이유를 원본에 적었다.** 사람이 고른 것이지만 *왜*가 없으면 다음 사람이 게이트로
   올린다. 근거는 **재현되지 않는 판정**이라는 것 — 같은 diff에 같은 지적이 다시 나온다는 보장이
   없고, 근거가 원본에 없을 수도 있다. 그런 판정을 완료를 막는 자리에 두면 통과 기준이 흐려진다.
4. **`03`에 새 절을 만들지 않았다.** 경고라서 되돌아오는 갈래가 없다. 갈래가 없으면 루프
   문서에 쓸 것이 없다. `§6.2`의 PASS 줄에 층을 끼우고 "지나가는 층"이라고 한 문단 적은 것이
   전부다. 지적을 고치기로 하면 **기존 반려 경로**(카운터 0)를 그대로 탄다 — 새 규칙을 만들지
   않았다.
5. **자기 검토의 한계를 적었다.** "지적이 없다는 결과는 *찾지 못했다*는 뜻이지 *문제가 없다*는
   뜻이 아니다. 자기 변경을 자기가 훑은 것이므로 통과 판정으로 읽지 않는다." 이 문장이 없으면
   `🔍 지적 없음` 코멘트가 머지 근거로 쓰이기 시작한다. `03 §6.3` 마지막 줄에도 같은 취지를 박았다.
6. **충돌을 지적과 갈랐다.** 검토 중 원본끼리 또는 Issue와 원본이 어긋난 것을 발견하면 그것은
   검토 지적이 아니다. `00-ssot.md §4`의 `NEEDS_HUMAN`으로 빠진다. 경고 층이 충돌을 "지적 1건"
   으로 삼켜 지나가는 것을 막는다.

Protect 단계만 돌렸다 (`ALLOW_PROTECTED` · 승인 4건 통과). 나머지 단계는 마크다운 변경이라
검사하지 않는다 — `07-pr-gate.md §4`와 같은 판단이다.

이번 층을 넣은 뒤의 전체 흐름.

```
… → PR → CI ─ FAIL·재현됨 ──→ 복귀 [카운터 이어감]
            │  └ FAIL·재현안됨 → NEEDS_HUMAN
           PASS
            │
       🔍 LLM 검토 (AI · 로컬)  ── 지적이 있든 없든 →  ┐  [경고 · 카운터 안 오름]
            │                                      │
            └── PR 코멘트 (양식 `03 §5`) ───────────┘
            │
       사람 검증 ─ 반려 → 복귀 [카운터 0]      ← 지적을 받아들인 반려도 같은 경로
            │
           통과 → 머지(사람) → 끝
```

## 5. 남은 것

| # | 항목 | 비고 |
|---|---|---|
| 1 | 검토 프롬프트·체크리스트가 없다 | `02 §5` 표의 "보는 것" 네 항목이 전부다. 실전에서 한 번 돌려보고 필요하면 그때 정한다 — 미리 정하면 원본만 늘고 안 쓰인다 |
| 2 | 돌렸다는 증거가 코멘트뿐 | 실행 주체가 CI가 아니므로, 검토를 건너뛰고 사람 검증으로 넘어가도 기계가 잡지 못한다. `02 §3`이 "돌리라"고 적었을 뿐 강제하는 것은 없다 |
| 3 | 지적이 계속 무시될 때 | 규칙상 정상이다(경고). 다만 매번 무시되는 지적이 쌓이면 층 자체가 형식이 된다 — 몇 번 돌려보고 판단할 것 |
| 4 | 워크플로 자동화 | 이번에 보류. CI로 옮기려면 실행 주체가 바뀌므로 `02 §5`의 "실행자" 행을 먼저 고쳐야 한다 |
| 5 | 폼 없는 Issue의 최대 횟수 기본값 | `03 §7` 미정 1번 — 이번 세션에서도 손대지 않았다 |
