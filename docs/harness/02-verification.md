# 02. 검증 규칙

> 이 문서는 **무엇을 통과해야 변경이 끝난 것인지**만 정한다.
>
> 재고 규칙과 아키텍처 규칙 자체는 여기서 정하지 않는다. 그것은 `docs/01-requirements.md`와
> `docs/06-architecture.md`의 몫이고, 이 문서는 그 규칙들을 **언제 어떻게 판정하는지**를 정한다.

## 0. 범위

| 정한다 | 정하지 않는다 |
|---|---|
| 검증의 층(기계·사람)과 각 층의 판정 방법 | 재고 개념·기능·업무 규칙 (`01`) |
| 공통 기계 검증의 단계 구성과 순서 | 데이터 모델·재고 처리 구조 (`06`) |
| 단계별로 무엇을 잡고 무엇을 안 잡는가 | 이번 작업의 범위와 종료 조건 (GitHub Issue) |
| 게이트와 경고의 구분, 검사 불능의 처리 | 최대 반복 횟수와 그 출처 (`03-loop.md`) |
| Issue 단위 검증의 형식과 대응 규칙 | 반복을 멈추고 사람에게 넘기는 시점과 형식 (`03-loop.md`) |
| 한 번의 실행 안에서 어느 단계가 멈추면 뒤 단계를 건너뛰는가 | 재시도 자체를 멈추는 기준 (`03-loop.md`) |

검증 항목의 **내용**은 원본에서 온다. 이 문서에 도메인 수치나 불변식 목록을 옮겨 적지 않는다.

두 벌이 되는 순간 어느 쪽이 맞는지 알 수 없어진다.

| 검증 항목의 출처 | 원본 |
|---|---|
| 제품 수용 기준 | `01 §7` 완료 기준 |
| 자동 테스트로 지킬 불변식 | `06 §9` |
| 재고 변경 경로 규칙 | `06 §2` · `§4.1` · `§7.5` |
| 보호 경로와 승인 형식 | `00-ssot.md §5` |
| 이번 작업의 종료 조건 | 해당 Issue의 종료 조건 |

## 1. 검증의 두 층

| 층 | 판정자 | 대상 | 현재 상태 |
|---|---|---|---|
| **기계 검증** | `npm run verify` | 코드·데이터 불변식, 경로 규칙, 타입·린트·빌드 | 확정 |
| **사람 검증** | 사람 | 시나리오 재현·반응형·엣지 케이스 (`07 §2 B~D`) | ⬜ 미정 |

**기계 검증을 통과하지 못한 변경은 완료가 아니다.** 사람 검증은 기계 검증을 대신하지 못하고,
기계 검증도 사람 검증을 대신하지 못한다.

## 2. 공통 기계 검증 — `npm run verify`

한 명령이 전부다. 단계를 낱개로 돌리는 것은 개발 중 확인일 뿐, 판정이 아니다.

```
Protect → Prepare → Types → Lint → Arch → Test → Domain → Build
```
